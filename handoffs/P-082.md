# Handoffs — P-082

## 2026-11-15 · human:Luis-Emidio
Design revisions from user review (2026-11-15) — fold into body when accepted:

1. SSR/no-flash/no-CLS is a hard requirement. Brand theme resolves
   server-side in the root loader (tenant/portal scope from session) and
   the var-override <style> + favicon links + title render in the
   initial HTML — no client-side detection, no theme flash. Brand !=
   light/dark: the plugin emits BOTH :root and .dark override blocks
   from the same seeds; .dark remains the user's mode preference.
   CLS guard: brand slot reserves a fixed aspect box for logo/wordmark;
   favicon never affects layout. Font tokens optional — flag webfont
   swap as a known CLS source if themes ever override --font-sans.

2. Asset uploads go through the async jobs pattern, not the request
   path: upload -> R2 (THEME_ASSETS_BUCKET binding, same shape as
   AUDIO_BUCKET) -> enqueue -> worker validates image, derives variants
   (favicon 16/32/180, resized logo svg/png/webp/avif, optional
   dominant-color extraction to suggest seeds) -> writes asset refs on
   theme_definitions. Surfaced in the jobs console feed like audio jobs.
   Port/adapter at the edge per ADR-0001; no sync image processing in
   the upload route.

3. Theme switch = headerAction chrome contribution into
   portal.header.actions with optionalDeps: [platformHeaderPlugin.id]
   — exact same graceful-degradation contract as jobs.header: renders
   only when the platform.header marker plugin is registered. Popover
   lists theme_definitions by scope for admin preview/switch.

4. CSS vars confirmed as the mechanism: ui globals.css uses
   @theme inline mapping --color-* -> var(--*), so Tailwind v4
   utilities resolve the custom property at runtime — overriding
   --primary & friends on :root/.dark re-skins every component.
   This is the shadcn/Tailwind-v4 model; no build-time per-tenant CSS
   needed.
