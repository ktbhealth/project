# Handoffs — P-096

## 2026-11-18 · human:Luis-Emidio
Refinements after review (all adjustments folded in):

SCOPE — bounded worker ops only. Ingress/stateful drivers
(github-webhook, sturn-poll, schedules) stay in-process in peregrin;
this proposal covers request→result ops (vcs/forge/myco verbs).

REQUIRED BEFORE BUILD:
1. ADR in peregrin for the driver: ops contract — invoke→op→event
   mapping, spawn lifecycle (spawn-per-invoke vs pooled serve),
   dry_run/secret semantics, retry interplay.
2. tamias-serve op grammar for driver dispatch — namespaced query
   (driver.lasius.cli.forge.pr.merge) vs {driver,op,args} envelope;
   pick to match existing op grammar.
3. Payload composition: ops driver must let a node echo selected
   incoming-event fields into the emitted event payload (e.g.
   pull_request.number/ref/base_ref alongside the op result) — this
   is what kills file-based state passing (prs/<sha> maps).
4. Typed errors: drivers should surface structured error kinds
   (conflict/validation/transport) so campaigns stop scraping
   stderr — phase 2, not blocking.

REFERENCE CONSUMER: ktbhealth workflows/pr-review (workspace PR #1)
— first campaign to adopt; shell+CLI remains the fallback until the
driver lands.
