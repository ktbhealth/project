TITLE:
react-start plugin's optimizeDeps.exclude of @tanstack/react-router causes duplicate React ("Invalid hook call") in fully-bundled SSR environments (e.g. @cloudflare/vite-plugin)

BODY:
### Describe the bug
When @tanstack/react-start runs in a Vite env that is fully bundled — the SSR env created by @cloudflare/vite-plugin (viteEnvironment: { name: "ssr" }), which sets resolve.noExternal: true and optimizeDeps.noDiscovery: false — dev SSR fails during renderToReadableStream with:
  TypeError: Cannot read properties of null (reading 'useContext')
Two React instances end up in the SSR module graph:
1. The pre-bundled node_modules/.vite/deps_ssr/react.js used by react-dom/server.
2. A second, unbundled React reached from @tanstack/react-router's raw ?v= module (it is in optimizeDeps.exclude), whose react import resolves outside the optimized-dep graph.
The router's React has a null dispatcher while bundled react-dom/server renders → invalid hook call on the first hook (useRouter inside HeadContent).

### Why it happens
tanstack-react-start:config unconditionally adds @tanstack/react-router and @tanstack/react-router-devtools to environments.ssr.optimizeDeps.exclude whenever server dep optimization is enabled. Under @cloudflare/vite-plugin the SSR env is meant to serve the entire graph through Vite, so excluded packages fall back to raw ?v= modules whose imports bypass dep-optimizer rewriting — producing the second React.
There is no supported config to undo this: merges concatenate arrays, so users cannot remove exclude entries; the only escape is mutating resolved env options in a later configEnvironment hook.
Follow-on variant of #7119 (closed): that issue was missing React optimizeDeps.include; here React IS bundled and the duplicate comes specifically from the router packages being force-excluded.

### Environment
- vite-plus / @voidzero-dev/vite-plus-core: 1.5.0 (reproduces on vanilla Vite too, per #7119)
- @tanstack/react-start: 1.169.4, @tanstack/react-router: 1.170.46
- @cloudflare/vite-plugin: 1.67.0, wrangler: 4.158.0
- react / react-dom: 19.2.x
- Bun workspaces monorepo; bun run dev → vp dev (workerd SSR)

### Reproduction
1. Any TanStack Start app with a React root route.
2. Add cloudflare({ viteEnvironment: { name: "ssr" } }) to vite.config.ts plugins + wrangler.jsonc.
3. vite dev / vp dev, load any page → SSR crashes with the error above.

### Current workaround (works, but ugly)
environments: { ssr: { resolve: { noExternal: ["@tanstack/react-router", "@tanstack/react-router-devtools"] } } }
plus a plugin after tanstackStart() with configEnvironment("ssr") that splices those two packages out of options.optimizeDeps.exclude (merge concatenates; cannot remove via config), plus a pre resolveId plugin (dev-only) pinning react, react/jsx-runtime, react/jsx-dev-runtime, react-dom, react-dom/server to the deps_ssr optimized entries.
Note: @tanstack/react-start and @tanstack/start-static-server-functions must stay excluded (virtual #tanstack-*-entry imports).
Our impl: apps/web/vite.config.ts plugins ktb:ssr-single-react + ktb:ssr-single-react-pin (repo: ktbhealth/product).

### Suggested fix
In tanstack-react-start:config's configEnvironment, when the server env has dep optimization enabled (optimizeDeps.noDiscovery === false — fully bundled envs like the Cloudflare plugin's), do NOT add the router packages to optimizeDeps.exclude — include them in the optimized graph instead. At minimum, document the noExternal + exclude-splice workaround for @cloudflare/vite-plugin users.

CONTEXT: verified against TanStack/router main — behavior unchanged, no upstream fix. Our workaround still needed. Workaround caveats: pin plugin assumes default node_modules/.vite/deps_ssr cacheDir; may become unnecessary once router is genuinely inside the Vite pipeline.
